# bnb-roblox

把 `~/code/game/BnB`（网页版泡泡堂）完整移植到 Roblox 的项目。服务端权威、纯俯视 2D、房间化对局。

- **服务端**：30Hz 固定步长运行纯 Luau 的 `Game` 引擎（从 BnB `server/game.js` 移植）。移动、碰撞、泡泡、爆炸、道具、坐骑、推箱、踢泡、遥控、针、被困、死亡、掉落、胜负全部在服务端判定。
- **客户端**：只做表现。用 `ScreenGui` 画布渲染地图、精灵、HUD、等待/选角、3-2-1、结算，并在两个快照之间插值。客户端不发送位置。
- **对局（M1）**：服务端可为同一服务器上的多个真人分别运行独立房间。当前每个真人进入自己的练习模式 1v1：等待 10 秒（最后 3 秒锁定选角，未选中的角色卡灰化）→ 选角色 → 3 秒倒计时 → 对战 Bot → 4 秒结算 → 自动下一局。`RoundState`、快照、`Fx`、`RoundEnd` 只发送给该房间的成员，房间之间互不影响。原有 6 人混合 Bot 模式不再对外提供，但引擎仍支持 N 人。
- **数据层（M2）**：玩家档案保存在 DataStore `BnB_Profiles_v1`，加载时用原子 `UpdateAsync` 获取会话锁；同一账号并发登录不会重复发物品。结算、离开、30 秒心跳和关服都会保存；免费库存与购买库存分桶记账。
- **对战桌子（M3）**：练习房间仍是默认入口；等待界面点“换桌”会先**离开当前房间**，再打开房间浏览器，可进入新的练习房间、快速对战或指定桌子。对战桌 2 名真人、无 Bot，最多 4 桌、每桌 4 名观战。满 2 人后自动倒计时 10 秒，开局锁定名单；离开会立即移除座位，倒计时中被离开打断会取消并回到等待，对战期间离开或掉线判负，整段无操作 20 秒也会判负。浏览器关闭按钮为“返回练习”，进入一个全新的练习房间。观战只读，观战者永远不会补入空位；对战者离开后，桌子等待新的玩家加入。战绩只在对战模式按规则写入 `stats.versus`。
- **常驻房、临时房主与密码**：4 张对战房在服务器生命周期内常驻，空房也保留。第一个入座的玩家是临时房主，可在等待阶段修改房名（最多 30 个 Unicode 码点，且至少 5 个可见字符；服务端经 Roblox 文本过滤）和设置/清除 4–6 位数字密码。房名输入框在 30 个 Unicode 码点处提前截断；零宽字符、不可见 Unicode 空格、双向控制和行分隔符会被拒绝。密码房需要正确密码才能入座或观战，快速对战会跳过密码房，密码本身永不下发给客户端。房主离开且仍有座位玩家时，房主转移给最早入座的剩余玩家，房名和密码重置；最后一名座位玩家离开后房主为空，观战者会被送回练习并收到提示。房名/密码只保存在当前服务器的内存中，重启即重置，不做跨服或 DataStore 持久化。
- **商店与道具（M4）**：只卖功能道具——逃生针（针 2）、遥控泡泡（遥控 1）、踢泡（踢 1）。购买走 Roblox Developer Product 原生购买窗口，每个商品一次购买 1 个，没有套餐、购物车或数量选择；上架状态与价格由 Roblox 管，客户端不读取 Robux 余额，只要 Roblox 允许就可以反复购买。**没有装备编辑**：对战每局开始时自动携带 `min(免费+购买库存, 上限)`，库存不足就带现有的；练习模式不携带、也不消耗任何账号库存（地图拾取仍正常出现和使用）。`profile.loadout` 只为兼容旧档案保留，服务端不再将其用于携带或编辑。商店、大厅“我的道具”和等待界面都会显示拥有数量及免费/购买分桶，等待名单、对局名单和观战者都能看到每人的实带数量。打开商店等同于退出当前房间：先释放座位（对战桌取消倒计时，练习房被回收），房间浏览器在商店背后打开；关闭商店后留在浏览器里重新选择练习或桌子。因此商店和 Roblox 原生购买窗口不会暂停任何人的倒计时。对战结算按“实际用了几件”扣库存，优先扣免费库存，地图拾取的道具只算使用、不会让扣库存超过本局带入数量。购买收据按 `PurchaseId` 幂等，先持久化再确认。角色皮肤本轮不做。
- **素材**：复用 BnB 的图片/音频。素材未上传时客户端自动降级为色块/文字，逻辑仍可完整游玩。

## 构建与运行

```bash
rojo build -o bnb-roblox.rbxlx
```

用 Studio 打开 `bnb-roblox.rbxlx` 直接 Play；或：

```bash
rojo serve
```

在 Studio 中通过 Rojo 插件连接。

> `default.project.json` 已关闭 Roblox 默认角色（`Players.CharacterAutoLoads=false`）、清空 3D 场地，并关闭 `StreamingEnabled`。当前每个真人会获得独立练习房间，因此 Max Players 不再是单局人数上限；双客户端验证 1v1 时保持默认即可，后续多房间压测再在 **Place → Game Settings → Players → Max Players** 调高（Rojo 无法写这个属性）。

## 数据层（M2）

玩家档案保存在 DataStore `BnB_Profiles_v1` 的 `Player_<UserId>` 键下。M2 写入并恢复选角（`settings.char`）；M3 开始累计 `stats.versus`（场数/胜/负/平）；M4 开始写入 `inventory`（每件物品的 `free` / `purchased` 两桶）和 `receipts`（已处理的购买收据）。旧档案里的 `loadout` 仍按 schema 归一化以保持兼容，但不再参与携带或编辑。`freeNeedle` 和 `currency` 仍按版本化 schema 预留，供 M5 接入。

- **会话锁**：加载只用原子 `UpdateAsync` 声明锁（`sessionId` + 每次加载唯一的 `lockId`）。活锁超过 120 秒才允许接管；同一账号并发登录时后到者加载失败，不会创建默认档，也不会重复发物品。`lockId` 防止同服旧 handle 在新锁接管后覆盖或清除新锁。
- **保存时机**：房间结算、`PlayerRemoving`、30 秒心跳、`BindToClose`。同一档案的保存和释放走串行队列；释放用一次 `UpdateAsync` 写入最终数据并清锁。普通 DataStore 错误保留 dirty 等下一次重试；只有锁所有权丢失才踢出并提示重新加入。
- **库存**：`consumeStock` 先检查免费 + 购买的总量，足够时先扣免费、再扣购买；不足时两桶都不变。
- **加载失败**：未开启 Studio API 访问、DataStore 不可用或档案损坏时不入座，直接踢出并显示原因；不会静默回退到内存档。
- **加载中提示**：档案加载期间服务端对 `GetSync` 返回 `{ phase = "loading" }`，客户端显示“正在加载数据…”并关闭输入；入座后服务端推送房间状态，客户端另有每秒一次、最多 60 次的轮询兜底，防止漏掉事件。轮询耗尽后显示“加载超时”和“重试”按钮。同一账号快速重进时，服务端会先等待旧会话释放（最长约 10 秒）；仍未释放则踢出并提示“账号数据正在同步，请稍后重新加入”。加载占位不会覆盖已收到的真实状态。
- **免费针规则常量**（`ProfileSchema`，可调）：`FREE_NEEDLE_GOAL = 5` 局得 1 根、`FREE_NEEDLE_START_PROGRESS = 2` 新手起点、`FREE_NEEDLE_DAILY_CAP = 3` 每日上限、`FREE_NEEDLE_STOCK_CAP = 4` 库存上限；发放逻辑属于 M5。

### Studio 前置

1. 将项目发布到一个**独立的测试体验**（Studio 的 DataStore 会写入该体验的生产数据）。
2. 在 **Game Settings → Security** 打开 **Studio Access to API Services**。
3. 用 Studio 打开构建出的 `bnb-roblox.rbxlx`（或 `rojo serve` 同步）再 Play。未发布本地文件或未开启 API 访问时，加入会被踢并提示数据加载失败。
4. Studio 的 **Stop** 不保证等待完整的 `BindToClose`。Studio 主要验证选角恢复和 API 关闭时的踢出；真正的关服保存请用发布后的测试体验或线上服务器验证，或离开前等一次 30 秒心跳。

### 验证

- 加入后等待档案加载再入座；选 `haidao`，完成一局或直接离开，重进后角色仍为 `haidao`。
- 停止服务器再启动，重进确认存档仍在。
- 关闭 Studio API 访问后加入，确认收到“数据加载失败”提示，且没有入座或覆盖档案。
- 同账号并发应由后到者提示“该账号已在其他服务器登录”。Studio 的 **Clients and Servers** 本地多客户端可用同一个 Studio 登录测试；锁、接管、fencing 以及真实账号在多个服务器间的并发由 `tests/profile/` 的 fake DataStore 覆盖。
- Output 不应反复出现 DataStore 或锁泄漏警告。

## 对战桌子（M3）

玩家加入后默认进入独立的练习房间。等待界面右上角“换桌”是**离开当前房间**，服务端确认离座后才会显示房间浏览器：

- **练习模式**：进入一个新的练习房间；当前已无旧房间可回。
- **快速对战**：优先补入等待中且无密码的空桌，其次在未满 4 桌时新开一桌；全部满员或加密且仍有观战位时进入观战。全部桌子满员/加密时提示“没有可直接加入的桌子”。
- **指定桌子**：列出房名、阶段、房主、座位、观战人数、是否有密码与是否可加入；密码房点击后先输入密码。桌面已满时仍可凭密码加入观战（最多 4 人/桌）。
- **返回练习**：关闭浏览器等同于选择“练习模式”，进入全新练习房间。

对战房在服务器生命周期内常驻：启动时预创建 4 张空房，默认名为“房间 1”…“房间 4”，空房不会因玩家离开而删除。第一个入座玩家成为临时房主，等待界面会显示房主与是否有密码；只有房主在等待阶段能看到“设置”，可改名或设置/清除密码。房名最多 **30 个 Unicode 码点**，且至少要有 **5 个可见字符**（输入框超过 30 个码点会提前截断），允许中文、英文、数字、ASCII 空格、标点、emoji 和 LF 换行（CRLF/CR 归一为 LF，首尾空白裁剪）；零宽字符、不可见 Unicode 空格（不换行空格、全角空格等）、双向控制字符和 Unicode 行/段分隔符会被拒绝。服务端会先经 Roblox `TextService` 过滤再保存；列表和标题中换行显示为空格。房主离开且还有座位玩家时，房主转给最早入座的剩余玩家，房名与密码一并重置。房主把最后一张座位也带走时，桌子清空并重置；观战者会被移到一个新的练习房间，并收到“房主为空”的提示。观战者不会补位。

状态机：空座 → 等待（1/2）→ 满 2 人后 10 秒倒计时 → 对战 → 4 秒结算 → 人数仍满足则自动再倒计时 10 秒。倒计时最后 3 秒锁定选角；倒计时中有人离开会立即移除其座位、取消倒计时并回到等待，不产生结算。打开“换桌”就是一次离座：旧桌的倒计时直接取消，不会在界面背后继续计时，也不会把浏览中的玩家拉回对局；浏览期间 `GetSync` 返回空，直到玩家选择练习或某张桌子。开局时锁定本局名单，之后加入的人只会观战；观战者不接收输入、不能放泡泡，只读订阅快照。观战者永远不会补入对战位，即使有人离座，空座也只能由新加入的玩家填上。房主、房名和密码都在内存中，服务器重启即重置；跨服房间暂不实现。

判负规则：

- 对战中离开座位或掉线，立即判负；对手获胜，退出者仍会进入结算。
- 对战开始后 20 秒内双方都没有任何有效输入/操作时：只有一方无操作则该方判负，双方都无操作则平局。
- 超时未分胜负是平局并计场数。

战绩规则（`stats.versus`）：

- 只有对战模式计入；练习模式不写战绩。
- 一局不足 15 秒不计；但**中途退出例外**，即使不足 15 秒也按负/胜结算，避免用退出规避战绩。
- 双方都必须至少有一次有效操作；任一方全程无操作的局不计战绩（包括无操作判负）。
- 超时平局计入场数和平局，不计胜；正常淘汰按胜/负计入。

### Studio 验证

1. 两个客户端都先看到自己的练习房间；在等待界面点“换桌” → “快速对战”，两边应进入同一张桌子。
2. 满 2 人后等待 10 秒自动开局；最后 3 秒角色卡锁定。倒计时中任一玩家打开“换桌”后，该玩家应立即离开原桌，另一侧应看到座位空出、倒计时取消并回到等待，不会再被拉进对局。浏览者点“返回练习”应进入一个新的练习房间。
3. 第三个客户端点“换桌”，在“对战桌子”中选择那张已满的桌子（行尾应为“观战”）；不要点“快速对战”——未满 4 桌时它会新开一桌。观战界面显示“观战中 · 不参与对战”，不能移动或放泡泡。
4. 一局结束后两个玩家不再需要点准备，应自动再倒计时；若有人离开，另一侧应看到“对手离开”的结算，空座保持空缺，观战者不会补位。
5. 中途关闭一个客户端，另一侧应立即获胜；服务端会结算。Studio 模拟玩家的档案键不是你的真实账号，真实账号的战绩/存档需在发布后的体验中验证。
6. 两个客户端进入同一张空桌：第一个入座者等待界面出现“设置”，改名并设置 4–6 位数字密码。另一个客户端刷新列表应看到新房名、“有密码”和房主名；直接点“快速对战”不应进入该桌，在列表中点该桌会先弹出密码输入框，错误密码被拒，正确密码可入座；第三客户端用同一密码可以观战。
7. 房主离开：剩余座位玩家立即成为房主，房名/密码恢复默认，列表和等待界面同步更新。让最后一名座位玩家离开：观战者应被送回练习房间，并看到“房主为空”的提示；原桌仍在列表中，显示为空房、无密码。
8. 尝试不雅或带控制字符的房名：服务端过滤/拒绝后不应原样显示；零宽字符、不换行空格、全角空格、双向覆盖字符和 Unicode 行分隔符应被拒绝；输入超过 30 个 Unicode 码点时应被截断；换行和 emoji 不应破坏列表或标题布局。确认客户端日志和协议数据中没有密码明文。

## 商店与道具（M4）

只做功能道具，不做坐骑/外观商店。商品目录在 `src/shared/Shop.luau`，上架映射在 `src/server/ShopConfig.luau`：

| 道具 | 入场上限 | 消耗规则 |
|---|---|---|
| 逃生针 | 2 | 每成功使用 1 根扣 1 |
| 遥控炸弹 | 1 | 成功放下一枚遥控泡泡扣 1 |
| 踢泡泡 | 1 | 本局只要成功踢到至少一枚泡泡扣 1 |

**进店即离房**：等待界面和房间浏览器里的“道具”按钮打开商店。从房间打开商店时，客户端先调用 `LeaveTable`，等同于一次“换桌”：座位立即释放，对战桌取消倒计时并回到等待，练习房被回收；商店快照在没有房间的状态下读取，商店背后会打开房间浏览器。关闭商店后玩家留在浏览器里，可重新选择练习或桌子。因此购买期间不会被旧房间拉回对局，也不会影响其他玩家的倒计时。

**自动携带**：没有装备编辑，也没有 `+/-` 或锁定窗口。对战每局开始时自动携带 `min(免费+购买库存, 上限)`：针最多 2、遥控最多 1、踢最多 1；例如只有 1 根针就带 1 根。购买后下一局自动生效，局中买进更多库存不会改变本局携带；等待名单、对战名单和观战者都能看到每人的实带。`profile.loadout` 仅为旧档案兼容保留，服务端忽略它。

**练习模式**：不携带、也不消耗任何账号库存。地图上刷出的道具仍会正常出现，可以拾取和使用；结算不会扣针/遥控/踢的库存。商店仍可打开和购买，购买只改变拥有数量。

**库存展示**：商店每行用大字号显示 `拥有 N        免费 f · 购买 p`，并说明练习不携带或对战的自动携带数量；大厅的“我的道具”显示已拥有道具及免费/购买分桶；等待界面显示自己的道具摘要。三者都是只读，没有数量选择。

**购买**：每个道具对应一个 Developer Product，客户端通过 `MarketplaceService:PromptProductPurchase` 打开 Roblox 原生购买窗口，每次点击购买 1 个。Roblox Developer Product 是固定价格、固定发放量的商品，API 不支持数量选择、购物车或合并支付，因此只能逐个弹出原生窗口；价格、余额和余额不足提示都由 Roblox 处理。服务器不读取 Robux 余额，也不限制购买次数，只要 Roblox 允许就可以反复购买。三个产品的 ID 已固定配置在 `src/server/ShopConfig.luau` 的 `PRODUCTS` 中；ID 由 Roblox 在创建 Developer Product 时分配，属于该体验的固定标识，修改产品名称或 Robux 价格不会改变 ID，删除后重建才会得到新 ID。若把项目发布到另一个体验并重新创建产品，需要替换成新体验的 ID；填 `0` 表示未上架。上架/换绑步骤：

1. 在 Creator Dashboard 的打赏/商业化页面为**已发布的体验**创建 3 个 Developer Products（逃生针、遥控炸弹、踢泡泡），设置 Robux 价格。
2. 复制每个产品的 **Product ID**，填入 `src/server/ShopConfig.luau` 的 `PRODUCTS[item].productId`；`amount` 固定为 1。
3. Roblox 的购买窗口和收据回调只在已发布体验中生效；Studio 本地测试可以点开窗口，但不能完成真实购买。
4. 重新构建/同步后进游戏，在商店里点“购买 1 个”验证；服务端只有把收据写入档案并完成 flushed 后才返回 `PurchaseGranted`，失败会返回 `NotProcessedYet` 由 Roblox 重试。

**消耗结算**：对战每局结束后（正常结算、中途离座、房间重置、关服）按本局实际成功使用数结算，**用了才扣、没用不扣**；每名玩家每局只结算一次。扣库存时先扣免费桶、再扣购买桶，最多扣到带入数量（地图上捡到的道具算使用，但不会多扣库存）。踢泡泡只有真正踢到泡泡才计 1。练习模式始终不结算、不扣库存，没有测试开关。

**角色皮肤（暂不实现）**：未来皮肤应作为独立于功能道具的外观目录，用永久解锁的 Game Pass（或等价的一次性解锁）销售，不进入 `inventory`，也不影响移动/碰撞/道具属性；档案预留 `profile.skins.owned` / `profile.skins.equipped`。皮肤对所有角色通用，渲染时仍需保留队伍颜色的可读性（例如保留队伍色描边或色块），不能因为皮肤让双方难以分辨。

**收据幂等与掉线**：已处理的 `PurchaseId` 存在档案里，重复回调不会重复发放；在线玩家先 grant 再 `flush`，只有持久化成功才让 Roblox 确认购买；玩家已断线或档案尚未加载时，走 `ProfileStore` 的 load/grant/save(release) 直接交易，购买不会因为离开而丢失。

### Studio 验证

1. 打开商店：三个道具应显示“购买 1 个”，页面上没有数量加减或装备编辑。把某个 ID 临时改回 `0` 后应显示“未上架”且按钮不可用；测完记得填回。
2. 大厅点“我的道具”：应显示当前拥有数量；等待界面应显示自己的道具摘要；商店每行应清楚显示 `拥有 N        免费 f · 购买 p`。
3. 在已发布体验中购买：Roblox 原生窗口应显示价格；每次只买 1 个，完成后商店库存和大厅/等待摘要刷新，重复收据不会重复加库存。
4. 练习模式：等待名单和局内实带应为 0；用掉地图拾取的针/遥控/踢泡后结算，拥有库存不变。
5. 对战：开局自动携带 `min(库存, 上限)`；库存只有 1 根针时应只带 1 根。购买后下一局自动生效，局中购买不改变本局携带。
6. 对局中拾取地图道具并使用：库存最多扣到本局带入数量，不会因为地图拾取而倒扣。
7. 对局中关闭客户端：重新进入后确认本局已用的道具只扣一次；购买收据不会丢。
8. 等待倒计时中打开商店：该玩家应立即离开原房间。练习房会被回收；对战房另一侧应看到座位空出、倒计时取消并回到等待。商店和原生购买窗口打开期间不会暂停任何人的倒计时；关闭商店后应回到房间浏览器，可重新进入练习或桌子。

## 素材管线（可选）

原始素材在 `../BnB/client/assets`。预处理后为 **61 张图片 + 10 段音频 = 71 个资源**，全部图片 ≤1024×1024，音频转 OGG：


输出：

- `assets/prepared/audio/*.ogg`
- `assets/prepared/manifest.json`（key、帧信息、尺寸）
- `tools/studio_asset_ids.json`（手动上传路径的 ID 模板）

生成后的资源 ID 最终写入 `src/shared/AssetIds.luau`（带 `rbxassetid://` 前缀，由脚本生成，不要手改）。**当前 71 个资源 ID 已全部填入**；任何一项为空时，客户端会对该项自动降级。

### 路径 A：Open Cloud 自动上传（推荐，可重复）

1. 打开 <https://create.roblox.com/dashboard/credentials?activeTab=ApiKeysTab>。
2. **Create API Key**，名称如 `BnB-Assets`。
3. **Access Permissions → Assets** 勾选 **Read + Write**（`asset:read`、`asset:write`）。
4. 可选限制 IP / 体验 / 有效期。
5. **Save & Generate Key**，key 只显示一次。**不要提交到仓库、不要贴到聊天里**，只在运行命令的 shell 中通过环境变量提供：

```bash
export ROBLOX_API_KEY='...'
export ROBLOX_CREATOR_TYPE=user      # 或 group
export ROBLOX_CREATOR_ID=12345678    # userId 或 groupId
```

先干跑确认清单：

```bash
node tools/upload_assets.mjs --dry-run
```

确认后再真正上传（外发操作，需自行明确执行）：

```bash
node tools/upload_assets.mjs --images-only
node tools/upload_assets.mjs --audio-only
# 或只传部分：
node tools/upload_assets.mjs --only=img_box,sfx_explode

# 上传完成后生成 AssetIds.luau：
node tools/gen_asset_ids.mjs
```

- 上传缓存写在 `assets/.cache/upload-cache.json`（已 gitignore），可断点续传。
- `--force` 会重新上传已有缓存的项目。
- 审核被拒/配额不足的项会保留为空字符串，客户端继续降级。
- 音频按 `explode → bomb_set → get → role_die → start → save → lose → draw → victory → BGM` 顺序上传。

### 路径 B：Studio Asset Manager 手动上传（无需 API key）

1. Studio → **View → Asset Manager → Images**，**Bulk Import** `assets/prepared/images`（单批最多 50 个，61 张分两批）。
2. **Audio** 标签页导入 `assets/prepared/audio`（10 个 OGG）。
3. 等待审核通过后，右键资产 → **Copy ID**。
4. 把 ID 填进 `tools/studio_asset_ids.json`（键名与文件名一致，例如 `img_box`、`sfx_explode`；可以只填数字，工具会补 `rbxassetid://`）。注意这必须是合法 JSON（最后一项后面不能有逗号），否则 `gen_asset_ids.mjs` 会报错退出。
5. 生成：

```bash
node tools/gen_asset_ids.mjs
```

Studio 映射优先于 Open Cloud 缓存，便于手动纠正。两条路径最终都只修改 `src/shared/AssetIds.luau`。

### 音频限制

- Studio 与 Open Cloud 共用音频上传配额：未验证账号约 10 次/月，实名验证后约 100 次/月。默认只传 9 个 SFX + 1 个 BGM。

## 网络协议

| Remote | 方向 | 内容 |
|---|---|---|
| `Input` | C→S | 方向数组，最多 4 个合法方向，最后按下优先 |
| `Action` | C→S | `"place"` / `"use"` |
| `SelectChar` | C→S | `"baobao"` / `"haidao"`（仅等待阶段有效） |
| `LeaveTable` | C⇄S | 无参数 → `{ ok, reason? }`；离开当前房间（等同于一次离座），成功后客户端才打开房间浏览器；商店入口也复用它 |
| `RoundState` | S→C | phase、roomId、mode、maxPlayers、计时、roster、yourId、grid、结算；对战房另有 roomName、hostId、hostName、hasPassword、isHost |
| `Snapshot` | S→C 20Hz | 玩家、泡泡、爆炸、道具、掉落、滑箱；grid 仅变化时附带 |
| `Fx` | S→C | 音效提示 |
| `RoundEnd` | S→C | 胜者/平局/用时/存活数 |
| `Notice` | S→C | 本玩家定向提示 `{ message }`，用于观战者被送回练习等临时通知 |
| `GetSync` | C⇄S | 初始同步（按服务器分配的房间，强制带当前地图，不消费广播 grid 标记） |
| `GetTables` | C⇄S | 对战桌子摘要：id、房名、房主、是否有密码、阶段、座位、观战人数、倒计时、是否可加入；不含密码 |
| `JoinTable` | C⇄S | `"practice"` / `"versus"` / 桌子 id / `{ mode, tableId?, password? }` → `{ ok, reason?, roomId? }` |
| `SetRoomConfig` | C⇄S | 房主设置 `{ name?, password? }`（password 为空串表示清除）→ `{ ok, reason? }`；仅等待阶段、仅房主 |
| `GetShop` | C⇄S | 无参数 → `{ ok, items, phase, mode, practice, reason? }`；`items` 含库存、免费/购买分桶、自动携带和可购买状态。用于商店及大厅“我的道具”只读摘要；客户端在 `LeaveTable` 后调用，因此通常是房间无关快照 |
| `ShopUpdate` | S→C | 购买成功后推送最新商店快照；客户端刷新但不主动打开面板 |

`Snapshot`、`RoundState`、`Fx`、`RoundEnd` 都由房间实例通过 `Net.send` 定向发送；`Notice` 也只发给单个玩家；`Net.broadcast` 仅保留给未来的服务器级通知。密码只存在于服务端房间内存，不会出现在 `RoundState`、`GetSync`、`GetTables` 或 `Notice` 中。
